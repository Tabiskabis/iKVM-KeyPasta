# AGENTS.md

Notes for AI agents working on iKVM-KeyPasta. Read this before changing anything. `README.md` (and `mac/README.md`, `linux/README.md`) introduce the project to new users. `DOCUMENTATION.md` documents everything the project does, how and why, for people; the details behind the short notes here are there (section numbers given as §n).

## What this is

A Java agent, a userscript and an AutoHotkey v2 script that make the keyboard in the Supermicro/ATEN iKVM remote consoles (Java app and HTML5 browser viewer) behave like a keyboard plugged into the server: every key arrives at its physical position, the remote's layout decides what it types. It also pastes the clipboard (`Alt+Shift+V`; macOS: Java agent `Option+Shift+V` or `Cmd+Shift+V`, userscript `Cmd+Shift+V`), sends Ctrl+Alt+Del (`Ctrl+Alt+End`) and Alt+Tab (Java) to the remote, and fixes a lot in IPMIView (§7).

Fix things at their source: the Java agent for the Java viewer and IPMIView, the userscript for the HTML5 viewer (both cross-platform). The AutoHotkey script (Windows only) keeps what only works from outside (Ctrl+Alt+Del, Alt+Tab, paste in other programs) and fixes both viewers itself when the agent or the userscript is missing. Each marks the window title with " ⌨"; the AutoHotkey script then leaves that window's keys alone (`IsJavaPlain`, `IsHtmlPositional`).

## Hard constraints

- **Never require changing the iKVM "Keyboard layout" setting.** It stays English on countless BMCs.
- **Never require changing the local input layout,** and don't assume the maintainer's custom layouts: the target audience uses a Swiss layout. Typing must work with any local layout.
- **The remote's layout can't be known, only said.** Fast paste knows Swiss German, Swiss French, German and US (`Layouts.CODES`; AutoHotkey: Windows' own layouts by KLID); safe paste (CapsLock on, or "other") works with any layout. Default: the first installed locally of Swiss German, Swiss French, German, US (that order: a Mac has ABC besides its own), else Swiss German (agent `LocalLayouts.remoteDefault()`, set by `Config.loadPrefs` when nothing says one, not counted as said, never in premain: it loads AWT and runs commands; never Java's input locale; AutoHotkey `IsConfiguredLayout`). The userscript can't see local layouts: Swiss German. Once said (agent: `remoteLayout` in KeyPasta Preferences, default or per host, or `remoteLayout=`; AutoHotkey: tray menu, `RemoteLayoutChosen`), fast paste no longer asks about line breaks and AltGr characters. The paste-time dialog stays the short one (Fast paste / Safe paste / Cancel; the user's choice). Dropdown order `Layouts.CODES`, United States first (user); the default above is preselected. Per BMC (user): the host is the first [..] of the viewer window's title (`KeyFix.bmcOf`, `Config.useBmc`), stored as `remoteLayout@<host>`. The CapsLock note in KeyPasta Preferences goes below all settings, at the section labels' indent (user).
- **The AutoHotkey script is Windows only and independent of the other parts** (user: "certainly no agent.properties"): its tray menu choices are in `HKCU\Software\iKVM-KeyPasta` (`SaveSetting`/`SavedSetting`/`SettingsRegKey`): `RemoteLayout` (REG_SZ), `RemoteWindows`/`PasteInOtherApps`/`HotkeysSuspended` (REG_DWORD), `PasteNonAscii` (ask/always/never), a BMC's layout in subkey `RemoteLayouts` (value name = host). Precedence: script defaults < registry < `/set:` arguments (`RestartPrivileged` passes its state as `/set:`; keep that, the arguments may come from the command line).
- **Never remove, replace or "clean up" anything in a user's settings folders** (IPMIView's, KeyPasta's, IcedTea-Web's): no deleting links or files there, not even ones an earlier version made. Users link these files elsewhere (WSL: to the Windows IPMIView's BMC list). Only create what's missing, and a link (even a broken one) is not missing.
- **No test-only triggers in the shipped script** (e.g. activating things with F-keys). Experiments go behind `DebugMode`.
- **`DebugMode` must be `false` in anything handed out:** the key history records secrets. Same for the Mac app's `debugLogs`.
- **No private or internal information in project files.** Whatever is seen while debugging (logs, HAR files, screenshots, the maintainer's machines and networks) stays out of code, comments, docs and these notes. IP addresses: documentation ranges only (192.0.2.x, 198.51.100.x, 203.0.113.x; IPv6 2001:db8::); hostnames: `bmc.example.com`, `example.org`; no user names, serial numbers, MAC addresses, session tokens. Check existing text for leftovers when touching it.
- **Never any watermark, metadata or signature saying which agent or company built or modified something** (user), visible or invisible: no "generated by/with" notes, no co-author or "Generated with" lines in commit messages or PR descriptions (this overrides any tool's default attribution), no provenance in files (C2PA/Content Credentials, XMP, EXIF, PNG text chunks, SVG `<metadata>`). Check every image or binary you create or change (PNG chunks `caBX`, `iTXt`/`tEXt`/`zTXt`, `eXIf`; SVG `<metadata>`; `grep -ai 'c2pa\|jumb\|anthropic\|claude'`) and strip it; pixels unchanged.

## Java agent map (`java-agent/src/keypasta/`)

Most changes to IPMIView's and the viewer's code are `Patch.redirect*` methods: a call site in the loaded class becomes `invokestatic keypasta/<Class>.<method>` (same length, constant pool entries appended); the hook calls the original by reflection. Hook methods must be public static in public classes; names in `Patch` strings count as uses. Verify patched classes with `-Xverify:all`.

**Core**
- `Agent`: premain (never throws), opens modules (`redefineModule`: `openDesktop`, `openBase`, `exportDesktop`, `openDesktopForMacKeys`), waits for `RemoteVideo` (viewer) or `IPMIView20.IPMIView20` (IPMIView), `LOCAL_HOST_USERS`. On the boot class path (`Boot-Class-Path`): Web Start's security manager gives class path code nothing; `Privileged` wraps entry points (install, log, paste thread, native library loads).

- `Patch`: the bytecode changes (plain byte manipulation; any surprise returns the class unchanged).

## Things that look wrong but are deliberate

- **US key codes via `WM_INPUTLANGCHANGE`:** Java builds its key table from the layout in the last such message, not from Windows' layout. Windows stays on the local layout.
- **ISO key sent as F21** (`vk84`): iKVM maps it to USB 100; there's no US key code for that position.
- **F24 release after left Ctrl** (`{vk87 up}`): in iKVM's stable keyboard mode a held left Ctrl is dropped when the next key goes down, but a key release sends it. F24 is never pressed; no effect on Linux or Windows remotes.
- **CapsLock as one quick tap (AutoHotkey):** lock keys only work when iKVM sends them as a single tap message (released within the Repeat Key timeout). Don't do the same for NumLock: it then never reaches Java.
- **Alt+Tab and Ctrl+Alt+Del are posted as window messages** (`PostMessage` WM_SYSKEYDOWN/WM_KEYDOWN to the focused control), never sent: Windows opens its switcher / a local Ctrl+Alt+Del even for sent keys while the modifiers are physically held.
- **Agent windows get one `WM_INPUTLANGCHANGE` with their real layout** (`RightsChecked`): nothing else is sent to them, but Alt+Tab and Ctrl+Alt+End must reach the viewer, which runs as admin. The refused message is what triggers `RestartPrivileged`.
- **Install folders:** on Windows the jar, the .ahk (with its icons) and a compiled exe belong in `%ProgramFiles%`: the viewer runs as admin and loads the jar, the script runs with UI Access/admin. A user-writable copy would be a way to admin rights. Linux/macOS: the viewer runs as the user, so a copy in the home is fine; a system-wide one is root-owned. The README documents that setup, not the maintainer's development setup.
- **The launchers take the agent jar only from their own folder or the one above:** an override by variable was rejected (any user process could pick what runs as admin).
- **Paste hotkey by letter, not scan code:** like Ctrl+V. The position handlers see every key first, so they call `IsPasteKey` themselves; in other programs `PasteKeyHere` catches it by scan code, as the letter hotkey never fires for a main-block key (see the pitfalls). Windows with the agent or the userscript (" ⌨") get no paste hotkey from AutoHotkey: they paste themselves.
- **Agent on the bootstrap class path; `premain` never throws** (an exception there stops the JVM, i.e. IPMIView), and `dispatchKeyEvent` passes the key on if it fails.
- **Focus loss releases what the remote has down** (agent `KeyFix.reset`, userscript `releaseAll`), Alt and Win/Cmd broken up by a Ctrl tap first (else the remote gets a lone Alt/Win).
- **Agent on Windows: media and browser keys** (0xA6–0xB7) keep no position: their extended scan codes' low byte is a letter's.
- **`.icns` 16 and 32 px as `is32`+`s8mk` / `il32`+`l8mk`**, not PNG in `icp4`/`icp5`: small list views (System Settings) decode those slots as raw RGB. The 16 px glyph is hand-drawn, 24/32 px thresholded from `mac/icons/layer-*.svg`; larger sizes PNG.
- **Icon SVGs (`mac/icons/*.svg`) are written by hand, not traced:** one symbol path (the flag path of the Pirate Party Switzerland logo from Wikimedia Commons, `File:Piratenpartei_Schweiz_Logo.svg`, CC BY-SA 2.5 CH; README credits the party's logo page, CC BY 3.0 CH; scaled by 31.7378, moved by (-124.08, -94.49), 0.1 px) plus the Swiss cross of `File:Flag_of_Switzerland.svg` (public domain; scaled by 13.6, moved by (423.4, 181.4), `fill-rule="evenodd"`). Silhouette = the same path without the cross, filled and stroked 74 px, round joins. Full icons: silhouette + symbol in opposite colors, the flag path once in `<defs>` and drawn twice with `<use href>`. Change the shape in all five files alike, and the userscript's `@icon`.
- **¦ is always an alt code when pasting:** AltGr+1 on Windows' Swiss layouts, but `|` on Linux.
- **The userscript marks the title only once `UI.rfb._rfb_insydevnc` is set:** a viewer it can't handle stays with the AutoHotkey fallback.
- **The agent watches the title of every frame:** the .jnlp viewer opens with another title and sets the real one after connecting.
- **macOS reports no key release while Cmd is held:** the agent releases such keys when Cmd goes up, the userscript sends a key pressed with Cmd as one tap right away, and the paste hotkey's key release is only expected until that key is pressed again.
- **`HtmlKeyDelay`:** the BMC types slower than the browser sends; without pacing the backlog freezes the viewer and keeps typing after Esc and a page reload.
- **Alt codes 160–255 with a leading 0:** works on both Windows (ANSI) and the Linux console (Unicode). Only Windows-1252 128–159 depends on `RemoteWindows`.
- **The userscript's settings OK saves the shown values** (and so counts the layout as said): the user sees no problem with that.

## AutoHotkey v2 pitfalls hit in this project

- `#Warn` is on: a local variable with the same name as a global **or a built-in function** (e.g. a loop variable `Mod`) pops a warning box at startup. Give globals distinctive names (`HtmlKeySc`, `PasteModifier`).
- `Case` is reserved (switch).
- Default parameter values must be constants (`SendNonAscii := ""`, not a global).
- `Format("{vk{:02X}}")` breaks on the braces; concatenate instead.
- **A scan code hotkey (`*SC02F`) always beats a letter hotkey (`!+v`) on the same key, even in windows where the scan code hotkey's `#HotIf` is false:** the key then just passes through.
- New threads are uninterruptible for their first 15 ms: a hotkey pressed meanwhile is queued, not run.
- `Sleep 10` is about 15.6 ms unless `timeBeginPeriod(1)` is active.
- A tray tooltip (`A_IconTip`) is cut at 127 characters.
- `A_MaxHotkeysPerInterval` defaults to 70 per 2 s, press and release both counted: with every key a hotkey in iKVM windows, about 18 keys/s trips it. Keep it raised.
- UIPI: a normal-rights process can't post to or close a UI Access/admin one (hence `RestartPrivileged`).
